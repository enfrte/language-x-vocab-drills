learn-language-x — Architecture & Reference

This document describes the complete application: what it does, how each module works, every class with its methods, the application flow and the offline/deployment story. It is the frontend-agnostic, language-generic rewrite of the learn-maori app; newcomer tutorial in docs/tutorial.html.

1. What the application is

A client-side PWA for memorising vocabulary. Frequency-ordered word lists are presented as "topics"; Learn mode teaches a batch of 5 words at a time, then tests recall in both directions (word → English, English → word) with multiple-choice questions; Recall mode drills the learned list with adaptive re-queueing. All progress persists locally on the device — no backend, no accounts.

3. Data model

3.1 Entry (dataset record)

{"xx": "whare", "gr": "noun", "en": ["house", "any building", "suit (cards)"]}

{ id: number     // positional index in the topic's .jsonl file — THE stable progress key
  xx: string     // word in the learned language (key LANGUAGE.code)
  grammar: string  // part of speech; may be ""
  meanings: string[]  // English meanings; may be []
}

Consequences: ids are dense 0..wordCount-1 per topic and stable while the file is not reordered. Reordering silently mis-correlates saved progress. Dangling ids (dataset shrank) are dropped gracefully by both sessions.

3.2 Dataset files (src/data/datasets/)

xx-en-dic-nouns-by-frequency.jsonl (1568 lines), …verbs… (630), …adjectives… (261), …adverbs… (31). Each is bundled into the JS bundle via Vite ?raw imports at build time — part of why the PWA works offline.

3.3 Progress records (Dexie table progress, database learn-language-x)

{ key: "in-progress:<topic>",  ids: [0,1,2,3,4] }   // current Learn batch
{ key: "learned:<topic>",      ids: […] }           // all completed words
{ key: "recall-index:<topic>", value: 12 }          // Recall resume position (canonical order)

Settings live in localStorage: { theme: "light" | "dark" }.

4.5 domain/RecallSession.ts — RecallSession

State: phase (loading | empty | quiz | done), origin (learned ids sorted ascending = canonical frequency order), live queue, pos, question, answeredCount/correctCount.

  • Resume: recall-index: value is clamped into the current queue.
  • Every question updates the saved index to the word's canonical position, so a reload mid-session resumes at the same dictionary word, not the reshuffled queue position.
  • Re-queue rules: right → word to the tail of the queue; wrong → +5 positions after the current one (REQUEUE_DISTANCE).
  • Dangling id: spliced out of the queue recursively; empty queue → done + index reset.
MethodSummary
async setup()Empty learned → empty; else prime queue and first question → quiz.
answer(option)Records pick, counts answered/correct. Null when nothing to answer.
async advance()Applies re-queue rules, then next question or done (index saved/kept current throughout).

5. Frontend contract

sequenceDiagram participant UI as Any frontend participant App as LearnXApp participant S as Session UI->>App: subscribe(render) UI->>App: openLearn('nouns') App->>S: setup() (resume / pick batch) App-->>UI: notify() → render reads state UI->>App: answer('house') App->>S: answer(option) App-->>UI: notify() UI->>App: advance() App->>S: advance() → next question / completeBatch App-->>UI: notify()

Renderers only ever read: view/topic/theme, session phase/getters, QuestionView snapshots, TopicSnapshots. They never import Dexie, never touch Entry internals beyond display, never re-implement queue logic.

6. Application flow

  1. Load. Demo main.ts boots theme class from persisted settings before first paint, installs the SW (auto-update), installs window.lex, subscribes to the app and resolves any deep link.
  2. Landing — snapshotAll() per topic: learned x/y (z%) · n in progress; "Recall" disabled until ≥1 learned word. Reset-progress (confirm) and theme toggle in the footer.
  3. Learn — #learn/<topic>; resume-or-pick 5 → review → Test me → xx-en → en-xx → promote → next batch → "learned everything" when exhausted.
  4. Recall — #recall/<topic>; endless practice of learned words with adaptive re-queue; resumes from the saved index; empty/done states handled.
  5. Theme — toggles instantly, persists, no FOUC.
  6. Deep links — every hashchange re-syncs; unknown topic → first topic, unknown hash → landing.

7. PWA / offline / Vercel

  • vite-plugin-pwa generates sw.js (Workbox) which precaches the hashed JS bundle (with the datasets inlined), CSS, HTML, manifest and icons — 13 entries at build time.
  • registerType: 'autoUpdate': new deploys activate in background and take over on the next navigation.
  • Manifest is generic (Learn Language X, maskable + regular icons copied from the original static assets).
  • Vercel: any account can import the repo; framework preset Vite (build npm run build, output dist); vercel.json rewrites unknown paths to index.html. Offline works because everything is precached on first visit.

8. Behaviour quirks preserved on purpose

  • Learn batch selection is deterministic: the next N words in frequency order (in the original the shuffle was commented out — an experiment left in place). If you want random picks, wrap pickUnseen's result in shuffle() — one line.
  • Recall is an endless practice loop: a right answer always re-inserts the word at the tail, so the queue never drains through normal answering; the done phase is reached only when dangling-id removal empties the queue. The session stays resumable via the saved canonical index.
  • Learning strings are presentation-adjacent: prompts ("How do you say X in Māori?") are built inside the sessions from LANGUAGE.name; keep it that way or move them to the frontends, but never hardcode a language.
